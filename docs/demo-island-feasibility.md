# demo 岛场景 —— 可行性分析

基准：现有代码（`Kast.Core` / `Kast.Godot`，Godot 4.7.2 + .NET 8）。日期：2026-10-12。

## 0. 工具类

`NStaticSpellSymbol3D`: 在3D场景中渲染NSpellSymbol（无动画），用于字牌

## 1. 文法

| 产生式 | 用途 | 例 |
|---|---|---|
| `N -> Vt Adv` | 及物动词短语名词化 | `go sea thing` → 船 |
| `N -> Vi Adv` | 不及物动词短语名词化 | 备用 |
| `N -> N Adv` | 名词 + 量词 | `plant more` → 森林 |

## 2. 词语

- big-small
- solid-air
- plant-animal
- leg-arm
- you-i
- go-look

| `NCube` | `thing` | — | 2.0 | 1 | 测试物体，请勿使用 |

| `NGrass` | `small plant` | `plant` | 0.4 | 0.4 | 无碰撞 |

**出生点** 森林内。
**通关条件：离开岛屿。** 岛外围一圈 `Area3D`（`ExitArea`）包住岛体，玩家离开即通关 → `LoadLevel(下一关 id)`（`NGame.cs:160-169` 已写 `SaveSystem.Current.LevelID`）。边界即"离开岛屿"的地形定义，不依赖船；跳海、飞离、被蜘蛛打飞都算。船与蜘蛛只作去向与阻碍，**不是通关前置**。

**字牌文案**（沿小径顺序刻）：

1. `that you be display`
2. `i be that i be`
3. 断臂所指地面刻字：`cast`

## 5. 先做灰盒

岛是内容量问题，核心机制只有一条闭环。

1. 在一块 `NStone` 上醒来；
2. `display` → 浮出它的游戏词形；
3. `be big-small` 作用于自己 → 缩放可见；
4. `be solid-air` → 连续施放可见逐渐浮起 / 沉下；
5. 字牌揭示 `be` 与 `cast`。

⚠️ 第 3 步暴露的坑：`ScaleChanger` 只改 `Type.Scale` 并 `UpdateMass`，**不同步碰撞体外形**（碰撞体由 `SetType` reparent，`NObject.cs:29-35`）→ 缩到很小会"看得见、碰不着"。此坑在灰盒阶段暴露最便宜，先搭岛会返工。

顺序：① 成对词 + `ScaleChanger` ② 词表 + 三条产生式 ③ 灰盒闭环 ④ 岛 ⑤ 蜘蛛 ⑥ 出生播种 ⑦ `ExitArea` 通关。
